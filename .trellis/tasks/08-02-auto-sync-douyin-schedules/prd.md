# TIANTI 5.0：自动同步抖音达人主页

## Goal

作为网站 5.0 版本，自动读取已收录达人的抖音主页简介与粉丝量，在达人详情页展示当前行程原文和简介中的小号链接，并把明确的深圳未来行程直接、幂等地同步为公开活动与达人阵容。

## User Value

- 不再逐位达人、逐条活动手工抄写深圳未来行程。
- 访客可在达人详情页看到更及时的抖音粉丝量、全部当前行程和关联小号。
- 已经发生的活动沉淀为历史记录，不因达人后来删除简介行程而丢失。

## Confirmed Facts and Constraints

- 当前站内已有达人、活动、阵容、公开详情页和后台编辑流程；未来活动目前依赖人工创建和加人。
- 达人资料用通用 `TalentLink { label, url }` 保存平台链接，尚无稳定的抖音账号标识、同步状态或同步开关。
- 当前活动保存会替换整份阵容，并把阵容来源清空；自动同步不能复用这种覆盖式写入语义。
- 生产形态为 Next.js/Vercel + Postgres/Drizzle；mock 和 Postgres repository 必须保持契约一致。
- 用户不能要求达人逐个 OAuth 授权。5.0 在现有 Git-connected Vercel 项目中采用独立 Python Service，参考并固定 `Johnserf-Seed/f2` 的已验证实现；抓取代码不进入 Next.js runtime，也不再使用外部 Docker 部署。
- f2 被测 commit 为 `7dab3e2ffffaa2535834d28fca99dbc2e89fa9d3`，Apache-2.0，Python >= 3.10。真实探针确认：空 Cookie 返回空响应并失败；使用 f2 生成的访客 `ttwid` 可取得 `status_code=0`、原始简介和整数粉丝量。
- f2 用户详情响应未提供已验证的简介 `@账号` 目标。真实小号链接必须来自权威响应或渲染后的真实 Douyin URL，不得按昵称猜测；最终提取方式是实施前验收门槛。
- 五条真实简介样本显示：行程可能有或没有“行程”标签，使用空格、`/`、`➡️`、换行等分隔，日期可能是 `8.7`、`815`、`4.23-26`，并混合城市、活动简称、括号备注、历史日期和无关联系方式。

## Requirements

### R1. 抓取范围与调度

- 系统只读取已配置主抖音主页的公开用户信息：原始简介、粉丝量、稳定账号标识和可验证的简介 `@账号` 链接。
- 5.0 不抓取或下载作品、图片、直播、评论或其他账号数据。
- 每天自动同步全部符合条件的达人一次。
- 后台提供全量和单达人“立即同步”；手动同步有冷却、并发限制、运行锁和重复任务防护。
- 单个达人失败不阻止同批其他达人；失败不得清空上次成功数据。

### R2. 达人详情展示

- 粉丝量只在公开达人详情页显示，以“万”为单位的紧凑格式展示；首页、达人卡片、达人列表和搜索卡片不显示粉丝量。
- 公开页面不显示粉丝量抓取时间；后台仍保存抓取时间用于同步和排障。
- 达人详情页展示最近一次成功简介中识别出的全部行程原文，包括历史和非深圳行程。
- 行程保持原始顺序、文字、活动简称和分隔内容；可以调整换行、间距和视觉层级提高可读性，但不得改写含义。
- 简介中所有带真实抖音主页目标的 `@账号` 都视为该达人的小号并显示为可点击链接，包括“小号”“日常夺舍”和“理想型”等上下文。
- 小号按目标账号去重，不重复显示主主页；无法取得真实目标时不猜 URL，并记录同步跳过原因。
- 商务手机号、QQ/微信号和其他无关简介内容不得作为行程或小号展示。

### R3. 行程解析与深圳写入

- 解析器同时保留用于展示的原文和用于业务判断的结构化结果。
- 支持样本中的标签、分隔符、单日、紧凑日期和日期范围；所有日期必须通过真实日历校验。
- 年份按 Asia/Shanghai 日期语义判断。无年份日期默认属于当前上海日历年；已经早于今天的日期不得自动滚动为下一年。
- 无日期、无明确城市、年份不确定、格式无效或已经过去的行程只保留在详情原文中，并记录跳过原因。
- 只有明确识别为深圳且日期仍在未来的行程可以直接写入公开活动；其他城市绝不创建或更新活动。
- 5.0 没有候选或人工审核队列；达到明确解析条件的深圳行程同步完成后直接公开。
- 深圳行程可只有“日期 + 城市”。活动名和场馆缺失时保持为空，不生成“待确认活动”等虚构标题；公开界面用事实性的日期和城市形成可读内容。

### R4. 深圳活动聚合

- 同为深圳且日期相同的兼容行程默认合并。
- 一个聚合活动的最早日期到最晚日期之差最多为 5 个自然日；不得通过相邻记录链式扩张成超过 5 天的活动。
- 两条行程都有明确且不同的活动名时，即使同日或位于同一 5 天窗口也不得合并，例如“金铲铲”与“和平精英”。
- 名称为空本身不构成冲突，可并入唯一兼容的有名称或无名称活动。
- 同一窗口存在两个以上互相冲突的有名称活动时，无名称行程不得被任意分配给其中一个，应保留为独立无名称活动。
- 每位达人保留实际出席日期；多日聚合活动的开始/结束日期取该组最早/最晚来源日期。

### R5. 人工活动保护与幂等写入

- 自动来源只有在现有人工活动同为深圳、日期范围重叠、活动名兼容且只有一个严格匹配时，才复用人工活动。
- 复用人工活动只增量加入带自动来源标记的达人阵容，不得修改人工活动的名称、日期、场馆或备注。
- 无法严格确认与人工活动相同时创建/复用独立的自动活动。
- 自动同步不得替换整份阵容；只可添加、更新或清理自身来源标记的阵容。
- 相同快照重复执行不会重复创建活动或阵容。
- 管理员编辑自动活动后，该活动转为人工管理，不再允许同步修改或删除其活动字段。
- 管理员手工移除自动未来阵容后，同一来源不得在下一次同步中立即复活。

### R6. 简介变化与历史保护

- 抓取、认证、频控、响应校验或解析基础设施失败，不得累计“行程消失”次数。
- 仍处于未来状态的自动行程第一次从成功快照消失时保留；连续第二次成功快照仍缺失时，才清理对应自动阵容。
- 未来自动活动只有在失去全部阵容、仍由同步管理且从未被人工接管时才可自动删除。
- 活动按现有 Asia/Shanghai 日期规则变为过去后即冻结为历史事实：简介删除或修改不得删除活动、移除达人阵容、缩短日期或清空内容。
- 人工活动、人工阵容和历史记录永不被自动清理。

### R7. 来源、状态与安全

- 保存当前同步状态、来源指纹、解析器版本、成功/跳过/失败结果和安全错误码，以支持幂等、清理和排障。
- 后台可查看每次同步的成功、跳过和失败汇总，但不需要逐条审批。
- Cookie、`ttwid`、签名 URL、共享密钥和完整上游响应不得写入网站数据库或普通日志。
- 抓取服务只允许受控的 HTTPS Douyin 主页 URL，防止任意 URL 请求和 SSRF。

## Acceptance Criteria

- [ ] AC1：有效主抖音主页可解析稳定 `sec_user_id`；独立服务可返回原始 `user.signature` 和非负整数 `user.follower_count`。失败保留上次成功数据。
- [ ] AC2：粉丝量只出现在达人详情页，以 `12.6 万` 这类格式显示；首页、列表、卡片、搜索和公开时间信息均不出现粉丝量。
- [ ] AC3：达人详情页按原始顺序展示全部当前行程文本；例如 `7.31 上海cj 8.1郑州 8.7成都 codm 8.8重庆 8.9上海闪魂绝区零` 不被改写、截断或丢段。
- [ ] AC4：简介中所有能恢复真实主页目标的 `@账号` 都作为可点击小号显示，包括“理想型”后的账号；重复目标和主账号被去重，无法验证的目标不被猜测。
- [ ] AC5：给定五条脱敏样本，只有两条 `8.8深圳金铲铲` 同步为同一个深圳活动并关联两位达人；成都、青岛、广州、上海、郑州、重庆等行程不写入活动。
- [ ] AC6：`8.8深圳` 可直接形成名称/场馆为空的公开活动，界面显示日期和城市，不显示虚构活动名。
- [ ] AC7：兼容深圳行程只有在最早日至最晚日之差不超过 5 天时聚合；超过 5 天另建活动。`8.8金铲铲深圳` 与 `8.8和平精英深圳` 始终分开；同窗口的无名称行程不会在多个冲突名称之间任意归属。
- [ ] AC8：严格匹配的人工活动只新增自动来源阵容，所有人工字段保持不变；不确定匹配分开。重复同步不产生重复活动或阵容。
- [ ] AC9：无日期、已过期、无法可靠解析或抓取失败的内容不污染未来活动；单达人失败不影响同批其他达人。
- [ ] AC10：未来行程连续两次成功快照都消失后才清理自动阵容；失败快照不推进清理。活动变为过去后，来源删除也不会改变历史活动或阵容。
- [ ] AC11：每日任务可幂等完成整批同步；后台全量/单达人手动同步遵守运行锁、冷却和并发限制，并显示安全的结果汇总。
- [ ] AC12：管理员手工创建、编辑或接管的数据不会被后续自动同步静默覆盖、恢复或删除。
- [ ] AC13：mock 与 Postgres 模式通过相同领域/仓储契约；真实 Cookie、共享密钥和签名 URL不进入公开状态、数据库快照或普通日志。

## Out of Scope

- 抓取达人作品、图文、评论、直播或直播状态。
- 开播提醒；架构允许未来扩展，但 5.0 不实现或展示入口。
- 粉丝历史、趋势图、排行榜或涨粉通知。
- 深圳以外城市的活动自动写入。
- 自动修改达人抖音主页。
- 展示商务联系方式、群号或与行程无关的简介内容。

## Technical Risks and Deferred Validation

- 抖音是非官方、易变化的数据源，存在 Cookie、频控、验证码、页面结构和服务条款风险；抓取服务必须可禁用、可替换并有安全错误分类。
- 实施前必须用至少一个“主简介包含可点击 `@账号`”的公开主页完成链接提取验收；可能需要仅在含 `@` 时启用 Playwright/Chromium。此验证不改变网站数据契约：链接只在真实目标可验证时展示。
- 当前手工活动名称必填、公共页面普遍假设名称非空；5.0 必须完整覆盖空名称自动活动的类型、写入、搜索、元数据和 UI 回退，不能只绕过校验。
- 当前 Postgres 关系替换缺少显式事务；活动聚合、来源记录和阵容增量写入必须作为一次原子 reconciliation 设计并验证。

研究证据见 `research/f2-profile-spike.md`，架构与执行细节分别见 `design.md` 和 `implement.md`。
